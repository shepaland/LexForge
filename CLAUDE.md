# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

LexForge — разработка нового скилла (skill) для кодовых агентов, который берёт сильные стороны
двух существующих систем и соединяет их в одну:

- **OpenSpec** — spec-driven разработка. Изменение проходит через артефакты
  `proposal → specs → design → tasks`, спеки живут в репозитории и обновляются при архивации.
- **superpowers** — библиотека процессных скиллов: brainstorming, TDD, systematic-debugging,
  writing-plans, verification-before-completion. Скилл принуждает агента к дисциплине
  до того, как он начнёт писать код.

От OpenSpec берутся артефакты и проверяемая структура требований, от superpowers — процессные
ворота (gates) и поведенческие правила для агента. LexForge должен дать и то, и другое в одном скилле.

В репозитории код, тесты, девять скиллов и выпущенная версия 1.1.0.

## Формат скилла

Скилл — это каталог с `SKILL.md`, у которого YAML-фронтматтер ровно из двух полей:

```markdown
---
name: kebab-case-имя
description: Use when <триггер> - <что делает>
---
```

По `description` агент решает, вызывать скилл или нет, поэтому там пишется момент срабатывания,
а не тема. Вспомогательные материалы кладутся рядом с `SKILL.md` отдельными файлами и подключаются
ссылками, сам `SKILL.md` держится коротким.

Раскладка при установке: скиллы плагина лежат в `skills/` репозитория плагина, личные скиллы —
в `~/.claude/skills/` (кросс-рантаймовый алиас `~/.agents/skills/`).

## Команды

Разработка самого LexForge идёт через собственный CLI `lexforge`:

```bash
lexforge new change <name>                              # новое предложение изменения
lexforge status                                         # готовность артефактов по change
lexforge instructions <artifact> --change <name>        # обогащённые инструкции для артефакта
lexforge validate <change> --strict                     # проверить артефакты (обязательно перед архивацией)
lexforge check plan --change <name>                     # проверить план перед реализацией
lexforge evidence record --change <name> --label tests  # записать доказательство прогона
lexforge check evidence --change <name>                 # проверить, что доказательства собраны
lexforge verify --change <name>                         # полная проверка change перед архивацией
lexforge archive <change>                               # архивировать change и влить дельты в основные спеки
```

Change без изменений требований (рефакторинг, тулинг, документация) обязан нести
`skip_specs: true` в `.lexforge.yaml`, иначе `validate` отвергнет его за нулевую дельту.
Выдумывать требование ради прохождения валидации нельзя.

## Как разрабатывается скилл

Разработка скилла — это TDD, применённый к документации процесса (см. `writing-skills`):

1. **RED** — прогнать сценарий давления на субагенте *без* скилла и записать точные рационализации,
   которыми он оправдывает нарушение.
2. **GREEN** — написать скилл, адресно закрывающий именно эти рационализации.
3. **REFACTOR** — искать новые лазейки, закрывать, перепроверять.

Скилл, который не проверяли на живом агенте, не считается написанным. Без наблюдаемого провала
неизвестно, чему он учит.

Порядок работы в сессии: процессные скиллы идут первыми и задают подход
(`superpowers:brainstorming` перед любым проектированием, `superpowers:writing-plans` перед
многошаговой работой, `superpowers:writing-skills` при работе над самим SKILL.md),
реализация начинается после них.

## Что попадает в репозиторий

Репозиторий несёт готовый продукт. Рабочие следы разработки остаются на машине.

**Коммитится:** `skills/`, `src/`, `bin/`, `schemas/`, `examples/`, `tests/`, `docs/`,
`package.json`, `README.md`, `LICENSE`, `CLAUDE.md`, `lexforge/specs/` и `lexforge/config.yaml`.

**Не коммитится:**

- Артефакты процесса: `lexforge/changes/`, `docs/superpowers/specs/`, `docs/superpowers/plans/`,
  `.superpowers/`, черновики планов, заметки сессии, отчёты прогонов субагентов. Они нужны
  разработчику в момент работы, пользователю продукта не нужны.
- Секреты: пароли, токены, ключи API, файлы `.env`, учётные данные npm и GitHub, содержимое
  `~/.claude`. Секрет не коммитится даже в примере и даже закомментированным.
- Локальные пути, конфиги IDE, кеши сборки, `node_modules/`, `dist/`.

Граница проходит по адресату: файл нужен тому, кто ставит LexForge, — коммитится; нужен только
тому, кто разрабатывает его в этой сессии, — остаётся локально. Дизайн-документы
в `docs/design/` описывают продукт и коммитятся.

Спека и change различаются по готовности. Change в работе — процесс, он остаётся локально.
Дельта, влитая в `lexforge/specs/<capability>/spec.md` при архивации, описывает поведение
выпущенного продукта и коммитится.

Перед коммитом проверяются `git status --short` и `git diff --cached`. Файл, попавший в индекс
случайно, снимается через `git restore --staged`. Пометка «уберу потом» не считается решением.

# Правила русского текста

Правила ниже перенесены из скилла `no-ai-slop-rus` и действуют для всего, что пишется
в этом репозитории: README, документация, proposal, design, tasks, тексты внутри
`SKILL.md`, сообщения коммитов, ответы пользователю. Действуют и когда правится чужой черновик.
Спеки в `lexforge/specs/` пишутся по-английски (`language: en` в `lexforge/config.yaml`) — эти
правила на них не распространяются.

Имена скиллов, поля фронтматтера, ключевые слова спеков (`ADDED Requirements`, `#### Scenario:`,
`WHEN`/`THEN`), команды и любые идентификаторы остаются в оригинальной форме.

Задача редактора: сохранить мысль и голос автора, убрать обороты, по которым читатель мгновенно
узнаёт нейросеть. Текст после правки должен звучать как написанный тем же человеком, только яснее.

## Две задачи

**Правка (по умолчанию).** Автор прислал черновик. Вносится минимальная достаточная правка
по правилам ниже, возвращается полный отредактированный текст плюс раздел **Что изменилось**.

**Поиск (detect).** Автор спрашивает, похоже ли это на нейросеть, просит проверить или разметить
текст без переписывания. Называется каждый найденный оборот из этого списка, цитируется строка,
в нескольких словах даётся замена. Текст не переписывается, оценка в баллах не выставляется,
утверждать, что текст написан машиной, нельзя: детекторы гадают, названный оборот с цитатой автор
проверит сам. В конце предлагается отредактировать.

## Что уточнить

Если черновика нет — попросить прислать текст.

Если непонятны читатель и площадка — задать один вопрос: для кого текст и где он публикуется.

Если непонятна цель — спросить, что читатель должен понять, почувствовать или сделать после прочтения.

## Принципы правки

- **Сохраняйте голос автора.** Сначала отметьте словарь, ритм, резкость, юмор, сомнение, отступления
  и степень отделки черновика. Личные черты оставьте. Не выравнивайте все абзацы под одну гладкость.
- **Минимальная достаточная правка.** Чините машинные обороты, ошибки, повторы и тёмные места.
  Живые сильные фразы не трогайте.
- **Начинайте с сути, если разгон ничего не даёт.** Пустой заход вырезается. Личное отступление,
  история или признание остаются, когда создают контекст или характер.
- **Не выдумывайте.** Утверждения, примеры, цифры, мнения не добавляются. Непонятное место —
  вопрос автору.
- **Не упрощайте до потери смысла.** Содержание, оттенки и точность остаются. Убирается то, что
  мешает читать: жаргон, длинные периоды, отглагольные существительные, запутанная конструкция.
- **Активный залог и живой глагол.** «Команда выкатила во вторник» вместо «релиз был осуществлён».
  «Приняли решение» → «решили», «осуществляет проверку» → «проверяет», «является причиной» →
  «вызывает». Неодушевлённое не совершает человеческих действий.
- **Конкретика вместо абстракции.** «Интеграция повысила эффективность» → «Интеграция сократила
  выкатку с 40 минут до 4». Имена, числа, даты, механизм, пример сильнее общих слов.
- **Проверка на переносимость.** Если фразу можно без изменений переставить в текст про другую
  компанию, страну или продукт — это наполнитель. Убрать или заменить фактом, механизмом,
  следствием, оценкой.
- **Показывать, а не объяснять читателю, что думать.** Смысл несут факты, действия и последствия.
  Комментарий о том, что мысль важна, неочевидна или тонка, удаляется.
- **Сохраняйте резкость и характер.** Сильные оценки, прямые формулировки, юмор, самоперебивы,
  честные признания остаются, если принадлежат автору. Не заменяйте их на более осторожные
  и «профессиональные».
- **Структуру не перекраивайте без нужды.** Если всё же меняете порядок — объясните в разделе
  «Что изменилось».

## Слова и обороты под замену

**Канцелярит.** Данный, осуществлять, производить (действие), являться, в целях, на предмет,
в части, в рамках, посредством, в связи с необходимостью, при наличии возможности.
Замена: этот, делать, быть, чтобы, для, по.

**Дутая лексика.** Погрузиться, синергия, экосистема (вне биологии), драйвер роста, инновационный,
передовой, уникальный, мощный инструмент, бесшовный, раскрыть потенциал, вывести на новый уровень,
краеугольный камень, золотой стандарт, квантовый скачок, знаковое событие, переломный момент,
многогранный, кропотливый, первостепенный, не что иное, как.

**Усилители без числа.** Критически важно, существенно повышает, значительно ускоряет, кардинально
меняет, максимально эффективно, поистине, по-настоящему. Либо число, либо ничего.

**Пустые вводные.** Стоит отметить, важно понимать, нельзя не отметить, как известно,
в современном мире, в современных условиях, в эпоху цифровизации, в конечном счёте, на самом деле,
по сути, что касается, давайте разберёмся, в этой статье мы рассмотрим, итак. Вырезаются, когда
оттягивают мысль. Одно-два остаются, если это узнаваемая речь автора и фраза несёт вес.

**Часто пустые наречия.** Просто, буквально, честно говоря, действительно, фактически, крайне,
весьма, безусловно, очевидно. Оставляются там, где несут сомнение, нажим или разговорный ритм автора.

**Бытовые метафоры.** Хозяйство, начинка, железо, кухня, прослойка, дверь в продукт.
Замена: инфраструктура, системы, сервис, оборудование, точка входа. Проверка: слово уместно
в деловой переписке средней компании и понятно человеку без технического образования.

## Обороты, которые вырезаются

**Антитеза «X, а не Y».** «Это решение, а не молчание», «вопрос не в модели, а в оценке»,
«не просто сервис, а платформа». Вторая половина отрицает то, чего никто не утверждал. Говорите Y
прямо: «Оценка важнее модели». Противопоставление остаётся, только если отрицаемый вариант —
настоящая альтернатива: «в постоянный каталог, а не во временный».

**Прочистка горла.** «Вот в чём дело», «скажу прямо», «давайте честно», «неудобная правда в том,
что». Вырезается, мысль остаётся.

**Псевдоинсайт.** «Вот о чём никто не говорит», «мало кто задумывается», «главное, что все
упускают», «этот шаг обычно пропускают». Заход выставляет автора единственным знающим. Убрать
заход, оставить утверждение: «Главное, что упускают: дистрибуция и есть барьер» → «Барьер —
дистрибуция».

**Двоеточие-раскрытие.** Существительное, двоеточие, эффектная концовка: «Главное: он учится сам».
Переписывается обычным предложением. Двоеточие — для списков, подписей и цитат.

**Поверхностный анализ на деепричастии.** «Подчёркивая приверженность команды», «отражая общий
тренд», «демонстрируя зрелость подхода». Заменяется следствием: «Добавили поиск по файлам, теперь
черновики находятся без выхода из редактора».

**Пафос значимости.** «Играет ключевую роль», «служит подтверждением», «закрепляет позиции»,
«открывает новую главу». Пишется факт, оценку делает читатель: «Запуск стал первым платным
продуктом компании».

**Метакомментарий.** «Здесь важно понимать», «как видим», «этот момент важнее, чем кажется»,
лишнее «иными словами». Если мысль ясна — удалить. Если нет — заменить фактом.

**Ссылки без источника.** «Эксперты считают», «исследования показывают», «многие полагают»,
«по мнению аналитиков». Назвать источник или снять утверждение. Источника у автора нет — спросить,
а не придумать.

**Синонимическая карусель.** Один предмет назван сервисом, платформой, решением и системой
в четырёх соседних предложениях. Точное слово повторяется столько раз, сколько нужно.

**Перечисление через отрицание.** «Не инструмент. Не платформа. Образ мышления». Пишется последнее.

**Драматичные обрывки.** «И всё. Вот и весь секрет», «Точка», «Работает». Пишутся полными
предложениями.

**Риторические вопросы и самоответы.** «А что если я скажу, что…», «Знакомо?», «Задумайтесь»,
«Что это значит? А значит вот что». Убираются, мысль формулируется прямо.

**Афористичная концовка абзаца.** Последняя «глубокая» строка, превращающая мысль в метафору или
чеканную формулу: «Дешевле, чем на аварии», «Будущее уже наступило». Удаляется целиком,
не переписывается в метафору получше. Абзац заканчивается самой конкретной фразой из уже
написанного. Одна такая строка на документ — приём, пять — привычка генератора.

**Итоговый пересказ.** «Подводя итог», «в заключение», «таким образом, мы рассмотрели» и финальный
абзац, повторяющий текст. Читатель только что это прочитал. Заканчивайте последним конкретным
выводом или следующим шагом.

**Самореференция.** Упоминания того, как документ сделан: сборка, генератор, реестры, проверки
связности, «в этом разделе мы приводим». Читателю это не нужно.

**«Чего» вместо «что».** «И чего не проверяли», «чего мы не просим», «то, чего сегодня нет»,
колонка «Чего стоит». Пишется «что»: «и что не проверяли», «что мы не запрашиваем», «то, что
сегодня отсутствует»; для колонки о цене решения — «Ограничения и риски». Формы с предлогом
остаются: «с чего начать», «из чего состоит», «от чего зависит», «после чего».

**Роботизированный ритм.** Одинаковые по форме предложения подряд, абзацы одной длины, лестница
коротких рубленых фраз, тройки ради ритма («быстро, надёжно, удобно»). Форма меняется там, где это
помогает мысли.

**Парные перечисления в каждом абзаце.** Тире и двоеточия, вводящие пояснение, в каждом втором
предложении. Оставьте один-два на текст, остальные разведите в обычные предложения.

**Тире вместо пунктуации.** Длинное тире как ритмический костыль. В коротком тексте — ни одного,
в длинном допустимы одно-два, если они очевидно лучше запятой, точки или скобок.

**Форматный мусор.** Эмодзи в заголовках, жирный посреди предложения, списки там, где хватило бы
двух предложений, заголовок над разделом в две строки. Формат следует за содержанием.

## Заголовки и подача

- **Заголовок называет содержание раздела, а не его жанр.** «Реестр находок» → «Что не так:
  находки с доказательствами». «Смета в трудоднях» → «Сколько это стоит в рабочих днях».
  Прочитайте оглавление вслух: звучит как перечень таблиц — переписывайте.
- **Раздел называется именем объекта, если объектов несколько.** «Площадка Б · боевая площадка
  продукта», иначе разделы не сопоставить между собой.
- **Карточка сущности подаётся таблицей «поле — значение».** В сплошном тексте пропущенное поле
  незаметно. Схема таблицу не заменяет, она иллюстрация.

## Порядок работы

1. Прочитайте черновик целиком.
2. Определите главную мысль и 3–5 признаков голоса, которые надо сохранить: словарь, ритм,
   резкость, юмор, сомнение, отступления. Заметку держите при себе. Главная мысль не читается —
   спросите автора.
3. Запрос на поиск — верните отчёт по разделу «Две задачи» и остановитесь.
4. Запрос на правку — внесите минимальные достаточные изменения и сами проверьте результат
   по чек-листу ниже.
5. Проверка провалена — исправьте и прогоните её заново.
6. Выдайте полный отредактированный текст и короткий раздел **Что изменилось**.

## Чек-лист проверки правки

Прогоняется после правки. На каждый пункт ответ «прошло» или «не прошло». Любое «не прошло» —
правьте текст и проверяйте заново.

Для запроса на поиск убедитесь, что в ответе назван каждый найденный оборот с цитатой и короткой
заменой, а текст не переписан.

**Принципы**

1. Мысль автора сохранена, новых утверждений, примеров, цифр, цитат и оценок не добавлено?
2. Словарь, ритм, резкость, юмор, сомнение и отступления автора сохранены?
3. Живые сильные фразы оставлены как есть, абзацы не выровнены под одну гладкость?
4. Объём вырезанного соразмерен реальному мусору, характер не сжат до конспекта?
5. Текст начинается с сути там, где заход ничего не давал, но личное отступление с контекстом
   сохранено?
6. Активный залог и живые глаголы вместо отглагольных существительных и пассива?
7. Канцелярит убран: «данный», «осуществлять», «являться», «в целях», «в части», «в рамках»?
8. Общие фразы прошли проверку на переносимость: убраны или заменены конкретикой по этому предмету?
9. Конкретные детали защищены и не сглажены в общие слова о важности?
10. Структура сохранена, а если менялась — это объяснено в разделе «Что изменилось»?
11. Запутанные предложения распутаны, при этом разговорный ритм и смена темпа не выровнены?

**Слова**

1. Дутая лексика, пустые вводные, часто пустые наречия и усилители без числа удалены, кроме
   случаев, когда они цитируются как пример?
2. Бытовые метафоры («хозяйство», «начинка», «железо», «кухня», «прослойка») заменены деловыми
   словами?
3. Каждый оставленный термин объяснён при первом появлении?

**Обороты**

1. Антитезы «X, а не Y», «не просто X, а Y», перечисления через отрицание и риторические вопросы
   убраны? Оставшиеся противопоставления держат настоящую альтернативу?
2. Прочистка горла, псевдоинсайты, двоеточия-раскрытия и драматичные обрывки убраны?
3. Пафос значимости и деепричастные хвосты («подчёркивая», «отражая», «демонстрируя») заменены
   фактами и следствиями?
4. Ссылки без источника заменены названным источником, сняты или помечены вопросом автору?
5. Метакомментарий убран: указания читателю, что важно, что очевидно и как понимать написанное?
6. Афористичные концовки абзацев удалены, а не переписаны в метафору получше?
7. Итоговый пересказ снят, текст заканчивается конкретным выводом или следующим шагом?
8. Самореференции нет: сборка, генератор, реестры, проверки в тексте не упоминаются?
9. «Чего» вместо «что» исправлено, формы с предлогом («с чего начать», «из чего состоит»)
   оставлены?
10. Синонимическая карусель убрана: один предмет назван одним словом?
11. Форматный мусор снят: эмодзи в заголовках, жирный посреди предложения, списки вместо прозы,
    заголовок над двумя строками?
12. Длинных тире не больше двух на длинный текст и ни одного в короткой заметке?
13. Парные перечисления через тире и двоеточия не идут в каждом абзаце?

**Заголовки и подача**

1. Заголовки называют содержание раздела, а не жанр?
2. Разделы с несколькими однотипными объектами названы по именам объектов?
3. Структурированное содержание подано таблицей «поле — значение», а не абзацами?

**Финальное чтение**

1. Правка проверена по этому чек-листу без отдельных агентов-редактора и агента-оценщика?
2. В тексте нет одинаковых по форме предложений подряд и лестницы рубленых фраз?
3. Автор узнает в отредактированном тексте свой голос?
4. Текст звучит естественно, если прочитать его вслух коллеге?
5. В ответе есть полный отредактированный текст и короткий раздел **Что изменилось**?
6. Для запроса на поиск: каждый оборот назван с цитатой и заменой, без переписывания, без баллов
   и без утверждений об авторстве машины?
