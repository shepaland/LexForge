# LexForge

## Пять команд

| Команда | Что делает |
| --- | --- |
| `lexforge init` | Создаёт каталог `lexforge/` с конфигурацией проекта и ставит скиллы для перечисленных агентов |
| `lexforge new change <name>` | Заводит каталог change и записывает в него схему артефактов |
| `lexforge status` | Показывает статус артефактов одного change или список всех активных |
| `lexforge instructions <artifact> --change <name>` | Отдаёт инструкцию, шаблон, контекст проекта и путь, куда писать артефакт |
| `lexforge validate <change>` | Проверяет артефакты и требования change; флаг `--strict` добавляет проверки полноты |

## Пять скиллов

`lexforge init --tools <список>` кладёт скиллы в каталог названного агента: для Claude Code
это `.claude/skills/`. Дальше агент выбирает скилл сам по строке `description`.

| Скилл | Срабатывает | Результат |
| --- | --- | --- |
| `lexforge` | Просят что-то построить, добавить, починить или разобрать, и ни один change этого не покрывает | Названный класс работы и заведённый change с нужной схемой |
| `lexforge-propose` | Просят proposal, или `lexforge status` показывает артефакт `proposal` в статусе `ready` | `proposal.md` из ответов пользователя: причина, выбранный подход, границы |
| `lexforge-spec` | Просят требования и сценарии change, или `lexforge validate` находит дефект в дельта-спеке | Дельта-спеки по возможностям с требованиями и сценариями `WHEN`/`THEN` |
| `lexforge-design` | Просят описать решения и их цену, и change идёт по схеме `spec-driven` | `design.md` из шести разделов, согласованных по одному |
| `lexforge-plan` | Просят план, список задач или разбивку по существующему change | `tasks.md`, где каждая задача называет файл и команду проверки |

Очередь держится на команде `lexforge status --change <name> --json`. Скилл запускает её
первой, находит свой артефакт в поле `artifacts` и смотрит на `status`: работать позволяет
только `ready`. На `blocked` скилл называет неготовые артефакты из `blockedBy` и
останавливается, на `done` показывает готовый файл и спрашивает про перезапись, на `skipped`
называет следующий шаг. Ветки «предупредить и всё-таки записать файл» нет: срок, размер
правки и просьба пропустить артефакт закрытые ворота не открывают.

## Коды возврата

| Код | Когда |
| --- | --- |
| `0` | Команда отработала, находок нет |
| `1` | Команда отработала и нашла нарушение: незакрытую зависимость, требование без сценария, оставшийся заполнитель шаблона |
| `2` | Команду нельзя выполнить: неизвестный аргумент, отсутствующий change, битое описание схемы, нет рабочего пространства |

Других кодов нет. Код `1` говорит о проблеме в проекте. Код `2` говорит о неверном вызове.

## Что читает скилл

Состояние change скилл узнаёт из флага `--json` и кода возврата. С этим флагом на стандартный
вывод уходит один документ JSON и ничего кроме него: строки для человека, сообщения о ходе
работы и подсказки печатаются в поток ошибок. Отказ при `--json` тоже приходит документом
JSON с полями `error.code`, `error.message` и `nextStep`.

Формулировки человеческого вывода меняются от версии к версии, разбирать их нельзя. Имена
полей JSON и коды возврата остаются прежними.
