# notes — изменение, прошедшее все ворота

**Русский** · [English](README.md)

Крошечная библиотека заметок и одно изменение LexForge на ней: `add-search`. Это то самое
изменение, что записано в [демо](../../docs/media/verify.ru.gif); оно лежит здесь, чтобы
артефакты можно было прочитать, а не смотреть.

```
lexforge/changes/add-search/
  proposal.md   зачем изменение, что увидит пользователь, чего оно касается
  specs/search/spec.md   одно требование, четыре сценария на WHEN/THEN
  design.md     два решения, у каждого — отклонённая альтернатива
  tasks.md      восемь задач; те, что несут требование, называют его
  evidence.json штампы: команда, её код возврата, коммит, рабочее дерево
```

Код — `src/notes.js` и `test/notes.test.js`: `npm test` гоняет шесть тестов, `npm run lint`
проверяет, что файл разбирается.

## Почему `verify` здесь не ответит 0

В `evidence.json` лежат штампы того прогона, который записан на видео. Их `head` и
`worktreeDigest` принадлежат тому репозиторию, а не вашему чекауту, поэтому
`lexforge verify --change add-search` отвечает `1` и называет доказательства несвежими. В этом и
смысл реестра: штамп доказывает, что команда отработала на конкретном дереве, и перестаёт
доказывать что-либо, как только дерево изменилось.

Чтобы увидеть зелёный ответ, запишите свои:

```bash
lexforge evidence record --change add-search --label tests
lexforge evidence record --change add-search --label lint
lexforge verify --change add-search
```
