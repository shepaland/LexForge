# Контекст задач и циклы исполнения

`lexforge context --change <name> --task <id> --json` возвращает задачи одного
поведенческого цикла, связанные требования и решения, файлы и символы, команды тестов,
базовую ревизию, актуальные доказательства и открытые замечания. Команда читает как
монолитный `tasks.md`, так и индекс файлов разделов. `--max-bytes` завершает команду
ошибкой при превышении размера; обязательные требования не обрезаются.

Новые изменения получают `workflow.json` с версией процесса 2 и схемы 1. Отсутствие
файла означает прежний процесс. Обновление скиллов само по себе не мигрирует изменение.
Для перехода существующего change создайте `execution-plan.json` и прочитайте отчёт:

```sh
lexforge workflow migrate --change <name> --to 2 --dry-run --json
```

Отчёт не меняет файлы; подробности доступны через `--task` и `--class`.
Историческое подтверждение требует задачи, критериев, состояния кода, успешного прогона
и независимого ревью. Галочка и общий штамп сами по себе этого не доказывают.
`workflow reconcile` и `workflow reconcile-review` закрывают пробелы текущей проверкой
и независимым ревью с происхождением `reconciled`, без выдуманного RED.

После разрешения миграции apply повторяет анализ под `execution.lock`, сохраняет
`migration.json` и переключает `workflow.json` последним. После прерывания повтор
завершает только совпадающую подготовленную запись; необъяснённые изменения блокируют
восстановление. Повтор успешной миграции при тех же входах ничего не записывает.
Установка пакета не разрешает миграцию. Несовместимые версии отклоняются.

`resume` и контекст показывают происхождение подтверждения. Смешанный цикл содержит
все исходные задачи и критерии, а `open_tasks` перечисляет только оставшуюся работу.
Зависимость готова, когда подтверждены все задачи предшественника. Поздние правки
сохраняют историю и отдельно делают текущие доказательства устаревшими. Свежие проверки
закрывают текущий пробел; изменение контракта требует нового reconciliation и ревью.
Verify и archive блокируют пробелы, конфликты и повреждение доказательств. Архивация
переносит неизменённый журнал вместе с change после проверки и до неё ничего не пишет.

[Формат sidecar и последовательность команд](../skills/lexforge-apply/execution-v2.md)
включены в устанавливаемый скилл. Sidecar связывает исходные task ID с критериями,
тестами, решениями и зависимостями. Тест, RED и GREEN являются состояниями одного цикла.

`cycle start` сохраняет исходные файлы. `cycle run --phase red|green` запускает команду
из плана и сохраняет полный лог, состояние кода, версии тестов, входов и среды. RED
требует ожидаемую полную строку assertion и exit 1; ошибки запуска и известные ошибки
компиляции не подходят. Ревьюер проверяет смысл падения. GREEN требует актуального RED.
Смена агента не является причиной повторного запуска.

`cycle review` принимает отчёт независимого ревьюера, привязанный к текущему GREEN и
патчу цикла. `cycle close` проверяет критерии, обязательные специальные проверки и
закрытие важных замечаний, затем сохраняет `continuation.json`. `resume` заново читает
первичные источники. `cycle restart` сохраняет предыдущую попытку и начинает новую с
теми же ID после изменения контракта.

Историческое доказательство подтверждает старое состояние. Для финального `verify`
текущие файлы должны совпадать с последними закрытыми снимками. Общие проверки проекта,
трассировка требований, реестр дефектов и ограничения размера файлов сохраняются.

`evidence record` и `evidence red` также сохраняют полный вывод в отдельные файлы.
Обычный ответ содержит итог и ссылку на лог; `--json` добавляет ограниченный хвост.
`--stream` включает прежний потоковый вывод. Старые записи реестров остаются читаемыми.

CLI проверяет заявленные входы и связи. Полноту критериев, выбор существенных внешних
зависимостей, квалификацию и независимость ревьюера подтверждает сессия, ведущая работу.
Для авторизации, криптографии, tenant isolation и миграций нужен соответствующий контроль.
Обращения к внешним сервисам требуют воспроизводимого состояния или повторного прогона.

Сокращение текста инструкций не измеряет экономию токенов всего процесса. Для оценки
нужны 5–10 сопоставимых циклов с раздельным учётом cached/uncached input, output, числа
запросов, повторных чтений/прогонов, времени, замечаний ревью и обнаруженных дефектов.
